CORE TECH 02

정규화 + 검증 파이프라인

우회 공격을 같은 기준으로 변환하고, 실제 적용 전 탐지율과 오탐률을 확인합니다.

1
Raw RequestWAF 로그와 요청 메타데이터 수집
2
Normalize인코딩·대소문자·주석 변형 정리
3
Detect토큰과 패턴으로 공격 의심 판단
4
Rule Generate조건 트리 기반 시그니처 생성
5
ValidateSandbox / Holdout / ZAP 검증
6
AI Report공격 설명과 개선 방향 요약
7
Deploy관리자 승인 후 WAF 반영

정규화가 필요한 이유

URL Decode Unicode Normalize Lowercase Comment Strip Token Analyze

공격자가 인코딩, 대소문자, 주석으로 우회해도 같은 의미의 요청으로 비교합니다.

검증이 필요한 이유

Sandbox: 생성한 룰을 가상 환경에서 먼저 공격 요청으로 테스트합니다.

Holdout: 룰 생성에 쓰지 않은 정상/공격 샘플로 오탐률을 확인합니다.

비동기 처리 구조

Redis + BullMQ가 ZAP 검증, AI 리포트 생성 같은 오래 걸리는 작업을 큐로 분리합니다.

OpenAI는 룰을 대신 배포하는 것이 아니라 공격 설명과 개선 제안을 제공합니다.
